# Downloading, choosing and posting: research and plan

Updated 2026-11-18. This plan identifies what is implemented and what still needs work. It is not a promise that every platform supports every function or that a free product can bypass platform approval.

## Current implementation

- Source and personal-profile video sync use the externally installed yt-dlp executable. TikTok, Instagram and YouTube channel links are accepted; a platform can block or change access. TikTok and Instagram photo support remains dependent on the optional existing helpers. YouTube channel acceptance is tested with synthetic files, not live downloads. The app does not currently sign in or extract browser cookies.
- yt-dlp is configured to save `.info.json`; when available, source listings read original post date, stable ID, title, description and original URL from the sidecar. Older files without metadata have unknown fields. The picker never treats download date as post date. It can filter by source, source category, original date and text; unknown dates can be included explicitly when filtering dates.
- Each posting profile has a persistent queue with original source-file references, optional planned local times, copied source details, a manually edited caption and explicit status. It blocks re-queuing the same known platform/post ID for that profile, including after status is recorded. If the post ID is unknown, duplicate detection is limited to the same source and path. When a source folder changes or a file is missing the queue marks it unavailable. No video is copied when queued.
- Profiles can schedule their own video sync while the app is open, with a tile countdown, using the same single downloader worker as sources. Auto-sync must be enabled by the user and is separate from the posting queue.
- Planned posting times are **not automatic publishing**, reminders, or background jobs. There is no category-level autopost, browser posting automation, content rewriting, file-to-clipboard, platform login, publisher API, or delivery verification yet. Nothing is published by this implementation.

## Publishing and scheduling research

- [TikTok Direct Post](https://developers.tiktok.com/docs/en/content-posting-api-get-started) needs an approved application, authorized `video.publish` scope and creator authorization. Unaudited clients have private-viewing restrictions. Its [content-sharing guidelines](https://developers.tiktok.com/docs/en/content-sharing-guidelines) describe creator consent, editable text and privacy requirements. A pre-set timer alone is not evidence the provider allows fully unattended publishing.
- Meta offers [Instagram Insights](https://developers.facebook.com/docs/insights/references) and [Instagram publishing permissions](https://developers.facebook.com/docs/instagram/platform/instagram-api/changelog/) for eligible professional-account integrations. Confirm the current exact API flow, account eligibility, app review, media hosting and supported content types before implementation.
- [YouTube videos.insert](https://developers.google.com/youtube/data/reference/rest/v3/videos/insert) supports authorized video uploads with OAuth and has upload quota/verification restrictions. Confirm scheduling, privacy status, project audit and API policy requirements for the user's channel before use.
- [Postiz](https://github.com/gitroomhq/postiz-app) is an AGPL-3.0 self-hosted scheduling system worth evaluating independently. It does not remove provider app approvals. Review license, deployment, authentication, supported platforms and data ownership before embedding or adapting it.

## Roadmap and acceptance criteria

1. **Candidate identity and metadata:** Index all source posts with platform, account, stable post/asset IDs and an immutable content reference. Preserve multi-image carousels as one post with multiple assets; current picker selects videos only. Add metadata-only refresh for archived posts and explicit unknown/error states. Keep original and download timestamps distinct.
2. **Picker and queue:** Add duration, media type, full-text, include/exclude source categories, before/after launch and explicit time-zone rules; record all filter values in a queue item. Persist optional note, planned time/zone and proposed caption, editing, cancellation, retry and clear duplicate policy. Add secure copy/open-in-file-manager actions and handle moved files. Existing queue history is manual and local.
3. **Review and AI drafting:** Explicitly prepare a caption based on the selected video, source text and the user's style, preserving attribution and content rights. Show preview, target account, caption, media, privacy, plan time and source to the owner. Never infer success from a click. Do not reuse another creator's content without appropriate permission.
4. **Supported account connectors:** Implement OAuth with PKCE where appropriate, state validation, OS-backed credential storage, scoped consent, logout/revoke and rate limits. Start with one provider and synthetic API tests. No raw browser-cookie harvesting. Clear account selection and reconnect errors are essential.
5. **Publishing worker:** Make per-profile and category automation explicitly opt-in; persist timezone-aware due times, deduplicate jobs and use a single lease/lock per item, exponential retry, pause/resume and a failure queue. Separate preparing, pending, uploading, published, failed and needs-user-action. Use provider idempotency/reconciliation before retrying a possibly completed upload. If an approved browser-computer-use workflow is used, handle login challenges, interrupted runs and platform UI changes; require an explicit, separate execution request and do not claim results until the platform confirms them.
6. **Validation:** Synthetic unit and integration tests for path boundary, missing files, duplicates, metadata dates, race conditions, scheduling across restart/DST and provider failure. Only then run explicitly approved tests on real user accounts, verifying the published URL and local status. Never start a real upload in normal automated tests.

## How to use the present queue

Open a posting profile → **Pick from sources** → choose filters → **Pick random** → optionally set a planned time → **Add to queue**. Use **Copy text** for the source title, description and link, **Open file** for the existing local video, and **Update status** after posting or reviewing. A later assistant can read these locally stored details, but there is currently no unattended posting worker.
