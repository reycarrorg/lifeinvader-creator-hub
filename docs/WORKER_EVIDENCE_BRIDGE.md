# Read-only Worker to Controller evidence bridge

Isolated incremental patch against exact d3f8f43 frozen overlay plus Controller patch SHA-256 6caae7504311fce9b4015898b01d62a7d01408eebb2487d9952d9c4a4df157a7. No Windows Stage 1 source/build, worker protocol or ledger changes.

New GET /api/controller/jobs/{id}/worker-evidence and per-job Check worker evidence button expose a separate observation, never overwrite durable Controller state/review or ingest a preview. Source currentness is checked before/after adapter read; any Controller job/revision change during read rejects the result. Archived/Solo/source binding restrictions use the existing source checks. Response is no-store, actions_enabled=false, retry_safe=false, review_required=true. No POST evidence route, publish action, retry, reservation, event write or enqueue. Existing OPS adapter remains unchanged.

Mapping: no trustworthy provider/missing or nonunique queue row => UNKNOWN; queue_hold => HELD; exact claimed render row => PROCESSING (observation, not fresh worker-liveness or retry authority); finished => READY_FOR_REVIEW only after exact reviewed binding, fresh observation, unique committed row, sidecar equality and artifact bytes/hash verification; incomplete/mismatched/stale proof => HELD. Other queue states map HELD/unmapped rather than guessing undocumented semantics. POSTED/BACKED_UP and approval are never derived from worker evidence.

Binding includes Controller job ID and revision, current source binding, and full SelectedCut (generation, provider/provider ID, source SHA/revision, start/end, recipe, durable cut key). Independently reviewed expected binding must exactly equal the current trusted observation; observations older than 30 seconds or in the future reject. Bridge uses the existing read_native_receipt implementation, requires an actually read-only SQLite connection, and consumes only already opened receipt/artifact Files. It checks complete bounded artifact bytes (16 MiB max), receipt digest/size and finished queue state again. No filesystem path or worker-supplied path is accepted by the route.

Integration boundary: Reader is trusted internal injection, default Unavailable. A concrete deployment must supply an independently reviewed job-to-cut registry and verified source/root/queue/receipt/artifact immutable leases for the whole observation, with a bounded read implementation and SQLite busy timeout. Controller v1 has no such registry; this patch deliberately does not infer authority from source_ref/name, wire live worker paths, or manufacture a production completion. A provider implementing Reader calls observe using those leases/bindings. The portable mapper cannot itself prove Windows lease provenance or source hashes merely from File handles. Its selection freshness is an observation timestamp and exact trusted binding, not proof that a claimed worker is alive. Thus this is a tested evidence adapter and visible read-only surface, not a connected production worker integration.
