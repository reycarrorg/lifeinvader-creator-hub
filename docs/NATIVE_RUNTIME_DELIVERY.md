# Native runtime delivery and app connection plan

Status: source design only; no installer, deployment or enabled render route.

## Normal app-to-worker connection

The existing `controller_supervisor::start` verifies exact executable/helper/approval/source pins, consumes the durable one-shot launch, starts an app-owned thread, bounds completion and imports the real read-only queue receipt. `Launcher` still has no installed production implementation. Connect it to `controller_native_process::Owned::gated_manifest` only after ASR inference qualification. The native bootstrap currently accepts diagnostic modes only: a separate strict reviewed-job mode must bind the exact Controller admission/worker job, review bytes, source/cut, full runtime and per-job producer config before calling `run_local`. Never make a diagnostic mode imply render permission.

Keep explicit manual admission separate from HTTP execution. A request can reserve and return an admission ID; the app-owned supervisor owns the child, retained leases, cancellation and completion. Unknown stale reservations HOLD. Import requires the exact worker job, durable proof, cut/source binding and output hash before READY_FOR_REVIEW. Do not repurpose the publishing ledger or modify raw hashed receipts.

## Versioned payload versus durable state

Deliver versioned known-source app, Python worker modules, explicit interpreter/dependency/model/tool manifest and provenance separately from writable Controller DB, queue, jobs, media and logs. No runtime/model or FFmpeg PATH fallback; no CUDA/NVIDIA driver bundling claim. Official installed Python/model provenance remains documented; byte manifests are not operator approval.

A build-only assembly must validate explicit inputs, schema/source revision and payload file hashes without executing a renderer, embedding credentials, copying private databases or enabling startup work. Preserve download marks and ordinary Windows prompts for downloaded inputs. Do not ship current ignored tools workspaces or copied venv as an assumed relocatable runtime; interpreter base references and DLL directories require an explicit install-location binding.

## Upgrade/recovery acceptance still needed

Close the exact owned app/worker normally; reject unresolved ownership rather than adopting it. Retain complete prior durable state. A SQLite backup must be a supported consistent snapshot, or a fully retained closed workspace including any WAL state; never copy only a live main database or detach its WAL. Upgrade must leave unknown claims HOLD and completed receipt/artifact bytes immutable. Rollback uses the preserved compatible payload/state, never automatic rerender. These are acceptance requirements, not tests performed in this ticket.
